# 文档批量处理工具

本地网页版小工具，处理 Word 文档的批量转换、清理、查找替换。

---

## 启动

### 方式一：打包版 exe（推荐，可直接分发）

双击 **`文档批量处理工具.exe`**（在 `dist` 目录里）。

- **单文件，目标电脑不需要装 Python**
- 首次启动慢 3~8 秒（单文件程序要自解压），之后正常
- 浏览器自动打开界面；关掉那个黑色命令行窗口即停止服务
- 绿色免安装：不写注册表、不装服务，放 U 盘也能直接跑

目标电脑要求：**Windows 10/11 64 位 + 已安装 WPS Office 或 Microsoft Word（装其一即可）**（程序靠它们读写文档）。
详见 `exe使用说明.md`。

### 方式二：源码运行

双击 **`启动(源码方式).bat`**，需要本机有 Python 3.9+ 及依赖：

```
pip install fastapi uvicorn pywin32 psutil
```

> `psutil` 只有「中断并清理进程」用得到（靠命令行区分工具自己起的实例和你手工打开的文档）。
> 不装也能跑，但那个按钮会退化成只看「有没有文档窗口」，判断精度差一点。

### 关于端口

默认从 **8770** 开始自动找空闲端口，不会因为端口冲突起不来。实际地址看命令行窗口第一行。
想固定端口，先设环境变量再运行：

```bat
set TOOLKIT_PORT=9000
```

### 关于文档引擎

程序启动时自动检测，**优先 WPS Office，其次 Microsoft Word**：

- 启动时控制台会打印检测结果，界面日志里也会输出一遍
- **检测通过后「docx 转换 / 开始查找 / 执行替换」才会亮起**；没检测到引擎时这三个按钮保持灰色，并弹窗提示「需要安装 WPS 或者 Microsoft Office，任务无法开始」
- 「doc 文件清理」不依赖办公软件（纯文件操作），不受影响

> 为什么优先 WPS：WPS 安装时会把 `Word.Application` 这个 COM 接口接管过去，而且会把 `app.Name` 伪装成 `Microsoft Word`。所以本工具走 `KWPS.Application`（WPS 官方接口），并靠 `app.Path` 判断实际引擎；只有确实没装 WPS 时才用微软 Word。

## 功能

### 第一步：选目录 + 预处理

**选择目录**：点「浏览」，在网页里从盘符开始逐层进入，到目标文件夹后点「就用这个目录」。也可以直接把路径粘进输入框。
**遍历所有子目录**：默认勾选。不勾只处理选中的那一层。

**「docx 转换」**
把目录里所有 `.doc` 另存为 `.docx`，放在原位置。
- **原 `.doc` 不动**（保留）
- 已有同名 docx 的会跳过，不覆盖
- 走本机已装的办公软件接口（WPS / Word 均可），格式不变

**「doc 文件清理」**
先排查、给清单、你再决定删什么。检查三类：

| 类型 | 说明 |
|---|---|
| 已有同名 docx | 这种 `.doc` 是转换前的原件，通常可以删 |
| 内容完全相同 | 按文件字节指纹比对，只抓**完全一样**的文件，保留一个 |
| 办公软件临时锁文件 | `~$` 开头的垃圾文件（WPS 和 Word 都会产生） |

排查完会列出表格，**默认全部勾选**，你可以取消不想删的。点「确认清理选中文件」后还有一道弹窗确认。

**删除是送进 Windows 回收站**，可以从回收站还原，不是永久删除。

### 第二步：查找与替换

左侧填查找内容，右侧填替换成什么。可以点「+ 添加关键词」加多行。

**「开始查找」**
只统计，不改文件。输出：
- 扫描了多少文件
- 命中多少文件
- 每个关键词出现多少次、分布在几个文件
- 有没有命中（能不能替换）

**「执行替换」**
真的改文件。会先弹窗列出所有规则让你确认。

**默认勾选「替换前备份」**，原文件会复制到目录下的 `_备份_时间戳`。
取消勾选就直接改，**没有后悔药**。

### 模糊匹配（可选开关）

勾选「模糊匹配」后，查找和替换放宽两条规则；不勾选就是普通精确匹配，行为和以前完全一样。

**① 日期格式等价**

下面这些写法会被当成同一个日期：

| 写法 | 归一结果 |
|---|---|
| 2025年1月20日 | 2025-01-20 |
| 2025.01.20 / 2025.1.20 | 2025-01-20 |
| 2025-01-20 / 2025-1-20 | 2025-01-20 |
| 2025/01/20 / 2025/1/20 | 2025-01-20 |
| 2025年01月20日 | 2025-01-20 |
| 2025年1月20号 | 2025-01-20 |
| 2025 年 1 月 20 日（带空格） | 2025-01-20 |
| 二〇二五年一月二十日（中文数字） | 2025-01-20 |
| 25.1.20 / 25年1月20日（两位年份） | 2025-01-20 |

所以搜索「2025年1月20日」，文档里写的是 `2025.01.20` 也能搜到并替换。

**只识别年月日齐全的日期**。像 `2025年1月`（缺日）、单独一个 `2025`、`二〇二五年` 都不会被当成日期，按普通文字处理。

**② 字符间空格容错**

搜索 `张二字`，能匹配 `张 二字`、`张  二  字`、`张　　二　　字`（全角空格）。

- **只容忍中间的空格**，匹配范围不包含首尾空格
- 搜索词本身首尾带的空格会自动去掉
- 替换时整段替换成你填的值（中间的空格随之消失），**前后的空格原样保留**

**替换值怎么写入**

不论匹配到的是哪种写法，一律替换成你在右格填的那个值，原样写入，不做格式转换。
例：搜索 `2025年1月20日` → 替换为 `2026年3月15日`，那么文档里的 `2025.01.20`、`2025-1-20`、`二〇二五年一月二十日` 全部变成 `2026年3月15日`。

**用的时候注意**

- 模糊匹配范围比精确匹配大，**务必先点「开始查找」看命中数**，确认没有误伤再替换
- 日期识别是按字面判断的，`2025.1.2` 这种既可能是日期也可能是版本号，无法区分
- 跨段落的匹配不会命中（比如一个词被分成两段写），这是有意为之，避免破坏段落结构

## 需要注意

**① 短名字会误伤**

查找替换只认字，不懂什么是人名。实测过：把「张三」换成「李四」，「张三丰」会变成「李四丰」。

所以：**先点「开始查找」看次数**。如果某个文件命中次数特别高（几百处），基本是误伤了，回去把关键词改长一点。

**② 文本框里的文字处理不到**

会处理的：正文段落 ✅ 表格单元格 ✅
处理不到：文本框（可拖动的小方框）❌ 页眉页脚 ❌

**③ 跑之前关掉办公软件里打开的文档**

文件被占用会打不开，那一份就跳过了。（WPS 或 Word 都一样）

**④ 「内容完全相同」只看字节**

两份文件文字一样但保存过（内部时间戳变了），字节指纹就不同，检测不到。这是正常现象，不影响使用。

**⑤ 一次只能跑一个任务**

任务执行期间按钮会禁用，等它跑完。

**⑥ 任务卡住不动：点「中断并清理进程」**

有些情况下 Word 会在后台弹一个看不见的对话框（文件被别的程序占着、要你选择"是否以只读方式打开"、
要不要另存为……），没人能点它，任务就一直停在那一份文件上：进度条不动、日志也不再新增。

这时点右上角的「**中断并清理进程**」，会先弹一个确认框（标题「确认中断？」，按钮是「取消 / 确认中断」），点「确认中断」才会真的执行：

- 结束后台运行的 Word / Excel / WPS 进程（工具自己起的那些；你自己开着编辑的文档默认不动）
- 删掉目录里的 `~$` 锁文件
- 卡住的任务立刻结束，已经写好的文件不受影响，卡住的那份记为「打不开」

判定标准：某份文件超过 `TOOLKIT_FILE_TIMEOUT` 秒（默认 90）没有响应，底部会出现红色提示条，
日志里也会写一条 warn。**先确认界面上确实没有 Word 弹窗，再点这个按钮**。

> ⚠️ **中断的代价**：强杀 Word 时如果它正在保存/转换某一份文档，**那一份可能写残**（已实测到一个这样坏掉的文件，Word 连"打开并修复"都救不回来）。
> - 替换任务开了备份，可以从 `_备份_时间戳` 里恢复
> - 转换任务没有备份，源 `.doc` 还在，重新转一次即可
> - 中断后**看一眼日志里最后那个文件**，必要时单独重跑它

为什么会有残留进程：任务中途被强杀（关掉命令行窗口、任务管理器结束、断电）时，Word 的自动化实例不会自己退出，它会一直占着当时打开的文档。
下次再处理同一份文件，就撞上「文件正在使用」的看不见的对话框。**所以中断之后最好顺手点一次这个按钮清干净**。

## 界面说明

- **顶部**：状态徽章（空闲 / 执行中 / 完成 / 出错）+ 右上角「中断并清理进程」按钮（任务卡死时用，任务执行中也不禁用）
- **左侧**：操作区，三步卡片
- **右侧**：执行日志。多任务的日志按时间顺序累积显示，每个任务的开始和结束用蓝色分隔线标出
- **底部**：进度条 + 当前处理的文件

### 日志

- 界面上的日志会持续累积，不会因为开了新任务就清空。点「清屏」只清屏上显示，不影响文件
- **每次启动程序生成一个独立日志文件**：`logs/run_20261113_095748.log`（`run_` + 启动时间）
- **程序一启动就开始写**：文件开头记录启动时间、程序目录、日志目录、引擎检测结果；之后每个任务依次追加
- 所以即使一次任务都没跑，点「下载」也能拿到带引擎检测的完整启动记录
- 只保留最近 **30 次**运行的日志，更早的自动清理
- 页面刷新后会显示最近的历史日志（最多 400 条）

**日志长什么样**

```
==============================================================
文档批量处理工具  启动于 2026-11-13 09:57:49
程序目录：E:\...\doc-toolkit
日志目录：E:\...\doc-toolkit\logs
--------------------------------------------------------------
文档引擎检测：
  WPS Office      可用
  Microsoft Word  未安装（Word 接口被 WPS 接管）
  使用顺序：WPS Office
==============================================================

[09:57:56][head] ────────────────  开始：关键词查找  ────────────────
[09:57:56][info] 扫描 2 个文件，1 个关键词
...
```

> 旧版本是按天合并（`20261024_执行日志.log`），那些文件是历史记录，留着备查，新版不再生成。

**任务日志的格式**

每个任务有明确的首尾分隔线，一眼能看出边界：

```
────  开始：批量替换  ────
扫描 3 个文件，1 条规则  【模糊模式】
模糊规则：日期格式等价 + 字符间空格容错；替换值原样写入
备份目录：D:\...\_备份_20261112_203322
已替换 SC-02设备管理办法.docx  （命中 3 处，写入 3 处）
已替换 SC-03环境管理制度1.docx  （命中 2 处，写入 2 处）
替换汇总：扫描 3 个文件，命中 3 个文件共 7 处，写入成功 3 个，失败 0 个
────  完成：批量替换，耗时 1.5 秒  ────
```

**「命中」和「写入」是两个不同的数**：
- 命中 = 找了多少处
- 写入 = 真正改成功多少处

两者不一致时说明有替换失败，日志会用 `error` 级别单独标出来，例如：

```
保存失败 xxx.docx << 文档保存失败  —— 命中 1 处但没写进磁盘
```

失败时任务也会补一条 `────  结束（异常）：...  ────`，堆栈信息逐行输出（最多最后 40 行）。

**几个交互细节**

- **「只看问题」**：只显示 warn 和 error 级别，排查问题时点它，噪音立刻少一半
- **滚动跟随**：日志自动跟到底部；你往上翻看历史时会自动暂停跟随，滚回底部恢复
- **服务重启**：如果后端重启，页面会提示"检测到服务重启，日志视图已清空并重新同步"并自动重连

> 早期版本是「一个任务一个文件」，那些文件（`20261024_153207_convert.log` 这种）是历史记录，留着备查，新版不再生成。

## 技术说明

- 后端：FastAPI + uvicorn，只监听 `127.0.0.1`，不对外暴露
- 文档处理：走 COM 接口调本机办公软件——优先 `KWPS.Application`（WPS），没有 WPS 时走 `Word.Application`（微软 Word），格式都不变
- 引擎判定只认 `app.Path`：WPS 会把 `Name` 伪装成 Microsoft Word、`Version` 伪装成 12.0
- 「中断并清理进程」的判定是三级，越靠前越可靠：① 命令行含 `/Automation -Embedding` = 工具自己起的实例，直接结束；② 命令行拿不到时看有没有「文档主框架窗口」（Word 是 `OpusApp`），有 = 你正在看，不动它；③ 连窗口都查不出来时保守不动，提示用强制模式。**宁可少杀，不误杀没保存的文档**
- 删 `~$` 锁文件前必须先确认没有任何办公软件进程在跑，且拒绝在整个盘根上执行
- 删除：`SHFileOperationW` + `FOF_ALLOWUNDO`（Windows 回收站）
- 备份/日志目录以 `_` 开头，遍历时会自动跳过，不会被重复处理
